# QA 测试人员工作流（详细版）

> 本文档是 [离线模式快速上手](./quickstart-offline.md) 和 [团队模式快速上手](./quickstart-team.md) 的「深度版」。读完前两个上手文档后，想更细致地了解脑图、状态、用例分类，就来这里。

---

## 你的一天大概是这样的

```
1. 浏览器打开脑图           ──────── 5 秒
2. 在脑图上选今天的范围     ──────── 5 分钟
3. 点节点 → 看步骤 → 测    ──────── 5–10 分钟 / 条
4. 标状态 + 写备注          ──────── 30 秒 / 条
5. 看进度条心里有数         ──────── 1 分钟
6. 阶段性导出 / 看一眼看板  ──────── 5 分钟
```

下面每个步骤都有详细说明。

---

## 1. 打开脑图

### 离线模式

双击 `.html` 文件 → 浏览器自动打开 → 直接看到脑图。

### 团队模式

打开浏览器 → 输入 `http://服务器IP:8765` → 粘贴 API Key → 进入项目 → 点左侧导航「Brain Map」。

---

## 2. 理解脑图

脑图（也叫测试用例图）由 **节点** 和 **边** 组成。

### 节点（Node）= 一个测试用例

脑图上每个彩色方块（也叫「节点」）就是一个测试用例。

![脑图节点 - 每个矩形就是一个测试用例，按标签分列、按类型分色](../screenshots/07-brain-map.png)

**节点上你能看到的信息：**

| 元素 | 含义 |
|------|------|
| 节点标题 | 用例简短描述（中文短句） |
| 节点边框颜色 | 当前状态（绿=通过，红=失败…） |
| 节点填充颜色 | 用例类型（浅绿=正向，橙=逆向，蓝=边界，红=安全） |
| 节点上的图标 | 标签（接口名 / 模块名） |

### 边（Edges）= 节点之间的关系

节点之间的箭头 / 线条：

- **从属关系**：父节点 = 一个接口，子节点 = 这个接口的不同测试角度
- **依赖关系**：A → B 表示「要先测 A 才能测 B」（例如 A = 注册，B = 登录）

---

## 4. 状态颜色的含义

脑图的颜色就是「测试状态」 — 一眼能看出哪些过了、哪些挂了。

| 状态 | 颜色 | 意思 | 什么时候用 |
|------|------|------|-----------|
| ⚪ 未测 (pending) | 灰色 | 还没测 | 默认状态 |
| 🔄 进行中 (in_progress) | 蓝色 | 正在测，测了一部分 | 你正在测这条用例 |
| ✅ 通过 (passed) | 绿色 | 测完了，跟预期一致 | 一切正常 |
| ❌ 失败 (failed) | 红色 | 测完了，跟预期不一致 | 有 bug 或者用例写错了 |
| ⏸ 阻塞 (blocked) | 黄色 | 暂时没法测 | 比如缺账号、缺环境、依赖其他 bug |
| ⏭ 跳过 (skipped) | 紫色 | 主动选择不测 | 比如重复用例、不适用的场景 |

### 标记状态的 4 个按钮

点击脑图上的任一节点，右侧详情区会出现 4 个按钮：

| 按钮 | 图标 | 含义 |
|------|------|------|
| ✅ Pass | 绿色对勾 | 标为「通过」 |
| ❌ Fail | 红色叉 | 标为「失败」 |
| ⏸ Skip | 黄色暂停 | 标为「跳过」 |
| ↩ Reset | 灰色返回 | 重置回「未测」 |

![右侧详情面板的 5 个状态按钮：通过 / 失败 / 阻塞 / 跳过 / 待测（v1 实际为 5 个按钮，不是 4 个）](../screenshots/08-case-detail.png)

**操作流程：**

1. 点节点
2. 右侧出现按钮
3. 点对应按钮
4. 节点边框颜色立刻变化
5. 顶部进度条更新

## 5. 写失败备注

**标「失败」后，必须在备注框写清楚为什么失败。**

### 好的备注（开发一眼看懂）

```
✓ 输入空用户名 → 返回 400 with "用户名不能为空"
✗ 实际返回 500 with stack trace 泄漏（安全漏洞！）
```

```
✓ 预期：未登录调用 /users/list 返回 401
✗ 实际：返回 200，body 是空数组（应该 401）
```

```
缺少分页参数 page=2 → 直接报 500（应该走默认 page=1）
```

### 不好的备注（开发看不懂）

```
不对
```

```
挂了
```

```
再看看
```

### 备注模板

拿不准怎么写时套这个模板：

```
【复现步骤】
1. ...
2. ...

【预期】xxx
【实际】xxx
【截图 / 日志】（如果有）
```

## 6. 用例类型（业务语言解释）

每个节点的颜色 / 图标代表「这是什么类型的用例」。你不需要背术语，但要大致知道每种类型在测什么。

### 🟢 正向用例（Positive）

**是什么**：按照正常的使用流程走一遍。

**例子**：

- 用户填正确的用户名密码 → 应该能登录
- 输入金额 100，下单 → 应该成功
- 不带任何可选参数 → 应该用默认值

**什么时候测**：先测这个 — 大部分功能正确性靠这个类型保证。

---

### 🟠 逆向用例（Negative）

**是什么**：故意搞破坏，看系统会不会拒绝。

**例子**：

- 密码填错 → 应该提示「密码错误」（而不是崩溃）
- 金额填 -100 → 应该提示「金额必须为正」
- 删除别人的订单 → 应该提示「无权操作」（而不是真的删了）

**什么时候测**：每一个正常路径，都对应着几条逆向用例 — casemap 会自动生成。

---

### 🔵 边界用例（Edge / Boundary）

**是什么**：测最边上、最极端的情况。

**例子**：

- 金额填 0.01（最小值）
- 金额填 999999999（超大值）
- 用户名填 50 字符（恰好到上限）
- 用户名填 51 字符（超过上限）

**什么时候测**：通常金额、长度、数量这些数字相关的字段必须有。

---

### 🔴 安全用例（Security）

**是什么**：测了别人能不能搞坏你的东西。

**例子**：

- 没登录调用 → 应该返回 401
- 用 A 用户的 token 操作 B 用户的资源 → 应该 403
- SQL 注入：用户名填 `' OR 1=1 --` → 应该过滤
- 重复点击提交按钮 → 应该只生效一次（防重放）

**什么时候测**：涉及权限、登录、支付的接口必须有。

## 7. 进度条怎么看

页面顶部会有一条横的进度条，类似这样：

```
[████████████░░░░░░░░] 60% (150 / 250)
```

**含义：**

- 数字 = 已测数 / 总数
- 百分比 = 完成率（通过的 / 总数，或：已标记的 / 数 — 看具体页面）
- 颜色：通常「通过」部分绿色，「失败」部分红色

### 进度条的局限

⚠️ 进度条只显示「测了多少」，不显示「测得好不好」。所以：

- 100% 但有 5 条失败 ≠ 100% 完成
- 报告给老板时，最好同时报：**完成率 + 失败数 + 阻塞原因**

## 8. 脑图上的辅助工具

### 搜索框

页面左上角（或脑图上方）有一个搜索框。输入关键词，回车后：

- 匹配的节点变金色边框
- 不匹配的节点变灰色 / 隐藏

**用法**：搜「登录」找登录相关的所有用例。

### 筛选器

通常有 3 种筛选：

- **按状态筛**：只看「失败」 / 「只看未测」
- **按类型筛**：只看「安全用例」
- **按标签筛**：只看某个接口 / 某个模块

### 缩放 / 平移

- **滚轮**：放大缩小
- **按住拖动**：平移视图
- **双击空白处**：回到默认视图
- **Ctrl/Cmd + 0**：浏览器级缩放重置

### 切换视图模式

通常有 3 种视图：

- **脑图视图**（默认）：可视化展示
- **表格视图**：以表格列出来用，可排序、可筛选
- **报告视图**：只读，干净，适合打印

## 9. 阶段性的导出

**不要等到测完才导出**。建议每测完一个接口 / 一个模块就导一次。

### 为什么要阶段性导出？

- 防止意外丢失（浏览器崩了、电脑坏了）
- 阶段性汇报给 PM
- 让开发提前看失败的 ticket，提前修

### 离线模式导出

页面右上角 → 「Export」 → 保存 `.json` 文件到公司网盘。

### 团队模式导出

- **报告 HTML**：给开发 / 老板看（只读）
- **状态 JSON**：用于跨设备同步（一般用不上，团队模式自动同步）

---

## 10. 跟团队的协作

### 实时同步（团队模式特有）

你标了什么，队友立刻看到。详见 [团队模式快速上手](./quickstart-team.md)。

### 沟通建议

- **有疑问**：直接在脑图节点上写备注（团队模式会带节点 ID 同步）
- **有发现严重 bug**：除了在脑图标记失败，**还要**在 IM / 邮件里 @ 开发
- **想确认优先级**：看 PM 是否已经标了「P0 / P1 / P2」（v1.1 功能）

### 不要做的事

- ❌ **不要** 把别人的失败改成通过 — 那是开发的事
- ❌ **不要** 把别人的备注删掉
- ❌ **不要** 看到别人的失败但是你不太确定 — 自己再测一遍确认

---

## 11. 一天结束

测试员一天结束时的「收尾」步骤：

1. **回到脑图页面**：看看今天测了多少条
2. **检查失败标**：今天失败的都有备注了吗？
3. **导出今天的报告**：保存到当天文件夹
4. **跟 PM 对一下**：进度是否对得上？有没有阻塞？

---

## 12. 测试员的「职业素养」 checklist

- [ ] 失败必写备注（不能只标失败）
- [ ] 备注里说「实际看到了什么」（不是「应该看什么」）
- [ ] 阻塞标清楚原因（不是随便标）
- [ ] 跳过的用例有理由（不是懒得测）
- [ ] 阶段性导出，不等到最后一天
- [ ] 发现严重 bug → IM 通知开发（不只等到报告）
