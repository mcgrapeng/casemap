# casemap 用户指南

> 欢迎使用 **casemap** — 把 API 接口文档自动变成一张可标记的「测试用例脑图」，让 QA 不用写脚本也能测，让 PM 一眼看清进度。

本文档面向 **QA 测试人员**、**产品经理 (PM)** 和 **业务方**。如果你想了解 casemap 的内部代码或部署细节，请看 [根目录 README](../../README.md)（开发者文档）。

## 5 分钟快速上手

casemap 有两种使用方式，从最简单的开始：

| 你属于哪种情况 | 推荐方式 | 文档 |
|----------|----------|------|
| 我一个人测一份接口文档 | **离线模式**：开发给我一个 `.html` 文件，我用浏览器打开就能测 | [离线模式快速上手](./quickstart-offline.md) |
| 我们团队好几个人一起测，老板要看实时进度 | **团队模式**：部署一台服务器，大家用浏览器一起看 | [团队模式快速上手](./quickstart-team.md) |

不知道选哪个？先看下面的「三种部署模式对比」。

> 💡 **第一次部署团队模式？** 跑一次 `casemap init` 走交互式向导 — 它会帮你生成管理员令牌、启动服务器、打开浏览器。详见 [团队模式快速上手](./quickstart-team.md#第一步半所有人必做--输入管理员令牌)。

## casemap 是什么？

想象一下：开发给了一份接口文档（Swagger / OpenAPI / Postman），里面有几十甚至上百个接口。传统做法是 QA 拿 Excel 表格一个个写测试用例、写步骤、执行、标记通过/失败 — 又慢又容易漏。

**casemap 做的事情是：**

1. **自动生成**：把接口文档解析成一张「测试用例脑图」，每个接口自动生成 5–15 条测试用例（正常、异常、边界、安全…）。
2. **可视化**：所有用例以脑图形式铺开 — 一眼看清有多少接口、用例之间什么关系。
3. **一键标记**：在脑图上点节点 → 看具体步骤 → 标记「通过 / 失败 / 跳过」+ 备注。
5. **团队实时同步**：你在 A 浏览器标记「通过」，同事 B 浏览器 1 秒内自动更新。
6. **导出报告**：测试完成后一键导出，发给开发或老板。

## 三种部署模式对比

| | 🅰️ 离线模式 | 🅱️ 团队模式 | 🅲 团队模式（含开发协作） |
|---|---|---|---|
| **适合谁** | 单个测试人员 / 临时一次性测试 | QA + PM + 业务方 | 加上开发（CI 自动上报） |
| **你需要什么** | 一个 `.html` 文件（开发给你） | 一台服务器 + 浏览器 | 团队模式 + CI 配置 |
| **数据存哪里** | 你电脑的浏览器里（`localStorage`） | 服务器数据库（SQLite） | 服务器数据库 |
| **多设备同步** | ❌ 需要手动导入导出 | ✅ 自动实时同步 | ✅ |
| **PM 看板** | ❌ | ✅ 自带进度页 | ✅ |
| **CI 自动上报** | ❌ | ❌ | ✅ 跑完单测自动更新状态 |
| **需要技术背景** | 零 — 只会用浏览器就行 | 一点点 — 启动一个程序 | 一点点 — 改 CI 配置 |
| **上手时间** | 5 分钟 | 15 分钟 | 30 分钟 |

**简单选法：**

- 你只是想测一下 → **🅰️ 离线模式**
- 你和同事要一起测 → **🅱️ 团队模式**
- 开发要把自动化测试结果接进来 → **🅲 含 CI 的团队模式**

## 常见问题 (FAQ)

**Q1：casemap 收费吗？**
A：完全免费，开源 (MIT 协议)。你可以自由部署到公司服务器。

**Q2：需要安装会操作吗？**
A：离线模式不需要安装任何东西 — 用浏览器打开 `.html` 文件就行。团队模式需要在服务器上装一次（一条 `docker run` 命令），之后大家用浏览器访问。

**Q3：接口文档有什么要求？**
A：支持 OpenAPI / Swagger / Postman / Apifox（JSON 格式）。如果你的接口文档是 Word、PDF 或 Markdown，casemap 暂时不支持 — 请先让开发导出 JSON。

**Q5：我不懂 HTTP, 什么是"接口"？**
A：「接口」就是程序与程序之间的约定 — 你手机 App 点一下「刷新」，背后就是程序去问服务器「给我最新的内容」，这个「问」的过程就是「调接口」。casemap 把所有这些「问」都画成脑图上的节点。

**Q6：脑图上的节点太多，我眼睛看不过来？**
A：用鼠标滚轮缩放，按住拖动可以平移；点击左侧筛选框只看「未完成」或「失败」的；用 Ctrl+F 搜索节点名。

**Q7：标记错状态了怎么办？**
A：再次点击同一个状态按钮（或点「重置」/ 「返回未测」），就能取消或改回。

**Q8：我测完了，报告怎么给开发？**
A：脑图页面右上角有「导出报告」按钮，下载一个 `.html` 文件，直接发邮件给开发就行 — 即使开发没装 casemap，他打开浏览器也能看（只读）。

**Q9：casemap 会上传我的数据到任何地方吗？**
A：离线模式 — 不会，所有数据存在你的浏览器里，关掉浏览器就清空了（如果没导出）。团队模式 — 数据存在你们自己的服务器，不上传任何第三方。

**Q10：老板问「测试进度怎么样」，我怎么回答？**
A：团队模式的「进度」页面有一张饼图 + 数字统计（通过 X 条 / 失败 X 条 / 完成率 X%），直接截图发给老板就行。

**Q11：浏览器顶部红色「no admin」徽标是什么？**
A：casemap v1.1+ 起列出/创建项目需要「管理员令牌」（部署时设置的密码）。在顶部输入框粘贴并按 Enter，徽标变绿就 OK 了。详见 [术语表 - 管理员令牌](./glossary.md#admin-token管理员令牌) 和 [团队模式快速上手](./quickstart-team.md#第一步半所有人必做--输入管理员令牌)。

**Q12：「项目 API Key」和「管理员令牌」有什么区别？**
A：管理员令牌 = 整栋楼的钥匙（谁能进门、创建项目）；项目 API Key = 每个房间的钥匙（谁能进这个项目改状态）。每个项目有自己的 API Key，由 PM 创建项目时分配。
