# 术语表

> casemap 用到的所有名词，按字母 / 拼音排序。每个词给出「业务语言解释」+「用户看到的名字术语」+「简短技术对应（可选）」。

---

## A

### admin token（管理员令牌）

**业务语言**：casemap 服务器部署时自己设的一个密码。控制「谁能列出/创建项目」这类管理操作。**没有它，浏览器顶部会一直显示红色「no admin」徽标，你看不到任何项目也不能创建**。

**用户看到的**：浏览器 UI 顶部那个输入框，红/绿徽标（红=no admin，绿=admin），或者一个弹窗（首次访问时）。

**怎么设：**

- 服务器启动前在终端设置环境变量 `export CASEMAP_SERVER_ADMIN_TOKEN="一段你自己定的密码"`
- 浏览器打开 UI 后在顶部输入框粘贴并按 Enter

**跟项目 API Key 的区别**：

- 管理员令牌 = 整栋楼的钥匙（能不能进门）
- 项目 API Key = 每个房间的钥匙（进了门能进哪个房间）

**怎么生成强密码：**

```bash
openssl rand -hex 16     # 32 字符随机 hex
openssl rand -base64 24  # 32 字符 base64
```

**技术对应**：env var `CASEMAP_SERVER_ADMIN_TOKEN`、浏览器 localStorage key `casemap.admin_token`。

---

### API（应用程序编程接口）

**业务语言**：程序之间相互对话的「合同」。比如手机 App 问服务器「给我最新的消息列表」，服务器回答「这是最新的 10 条」 — 这就是一次 API 调用。

**用户看到的**：开发给你的「接口文档」里列的每一条 `GET /xxx`、`POST /yyy`，就是一个 API。

**技术对应**：HTTP endpoint / REST resource。

---

### API Key（项目密钥）

**业务语言**：casemap 项目的「门钥匙」。PM 创建项目时会拿到一串字符（40+ 字符），发给测试人员和开发。这串字符决定了「谁能读写这个项目」。

**用户看到的**：一串像 `sk-casemap-7f3a9b2e8c1d...` 的字符串。

**怎么拿到**：

1. 在 casemap UI 点 **「New Project」** → 填项目名 → Create
2. 弹窗里显示 40+ 字符的密钥，**点 Copy 按钮复制**
3. 妥善保存（密码管理器 / 公司文档）
4. 关掉弹窗（**密钥不会再次显示**，丢了就重新创建项目）

**技术对应**：Bearer token、数据库里存的是 sha256(raw_token) 哈希。

**重要**：只显示一次，要立刻保存；等同于门钥匙，发给需要的人。

---

### Project API Key（项目密钥）

同 [API Key（项目密钥）](#api-key项目密钥)。这是「项目密钥」的完整名称 — 项目页面上叫 `Project API Key`，跟「管理员令牌」（admin token）区分。

---

## B

### 边界用例（Edge / Boundary Case）

**业务语言**：测极端情况 — 最小值、最大值、刚好到上限、超出一致、空字符串、超长字符串。

**例子**：金额填 0.01 / 999999999；用户名填 50 / 51 字符。

**用户看到的**：脑图节点是**蓝色**填充。

**技术对应**：boundary test、edge case test。

---

### 标签（Tag）

**业务语言**：用例的「分类」。casemap 自动给用例打标签，比如接口路径（`/login`）、用例类型（`positive`）、模块名（`订单`）。

**用户看到的**：脑图上每个节点有 1 个或多个标签，可以在筛选器里按标签看。

**技术对应**：tag、label、category。

---

## C

### CI（持续集成）

**业务语言**：开发每次改完代码，自动跑一遍自动化测试，确保没改坏。casemap 可以让 CI 把测试结果自动报给脑图。

**用户看到的**：脑图节点上会有「来源：CI」的标记，表示不是 QA 手工标的，是程序自动测的。

**技术对应**：Continuous Integration、Jenkins、GitHub Actions、GitLab CI。

---

### CI 上报（CI Report）

**业务语言**：让自动化测试结果自动出现在脑图上。开发改 CI 配置，跑完测试后 casemap 服务器会收到结果，对应脑图节点自动变色。

**用户看到的**：不需要任何操作 — 节点会自动变绿 / 红。

---

## D

### 导出（Export）

**业务语言**：把脑图 / 测试进度保存到本地文件，可以发给同事或存档。

**用户看到的**：脑图页面右上角「Export Report」按钮，下载一个 `.html` 文件。

---

## F

### 反向链接 / 报告链接

**业务语言**：casemap 生成的只读报告链接，可以发给老板 / 开发。打开只能看不能改。

---

## G

### 高级视图（Advanced View）

**业务语言**：脑图的高级操作模式，通常包括搜索、筛选、按 tag 分组、批量操作。

---

## H

### HTML 文件（离线模式）

**业务语言**：casemap 把整张脑图 + 所有数据 + 状态保存到一个 HTML 文件里。你只要用浏览器打开这个文件就能测，不用联网、不用装任何东西。

**用户看到的**：开发通过邮件 / IM 发给你的 `cases.html` 或 `项目名.html` 文件。

**技术对应**：自包含 HTML（self-contained HTML），所有 CSS / JS / 数据内联。

---

## J

### 进度条

**业务语言**：脑图页面顶部的横条，显示「已测 / 总数」的占比。

**用户看到的**：`[████████████░░░░░░] 60% (150 / 250)`

---

### 节点（Node）

**业务语言**：脑图上的一个「方块」= 一个测试用例。

**用户看到的**：彩色方块。颜色代表状态（绿=通过、红=失败…）。

**技术对应**：SVG `<g>` element、graph node。

---

## K

### 可视化（Visualization）

**业务语言**：用图代替表格 — 一眼看出有多少用例、哪些挂了、哪个模块进度慢。

---

## L

### LLM 重写（LLM Rewrite）

**业务语言**：casemap 调用大语言模型（ChatGPT / DeepSeek / Qwen …）把英文 / 程序员术语翻译成「人话」。让 QA 看用例时不再需要懂技术。

**用户看到的**：脑图上的用例描述都是中文业务语言（「用户能在不传用户名的情况下注册」），而不是英文术语。

**技术对应**：OpenAI-compatible API。

---

### 离线模式（Offline Mode）

**业务语言**：casemap 的最简模式 — 一个 HTML 文件，用浏览器打开就能用，不需要服务器。

**适用**：单个测试人员、不能装服务器的环境、临时一次性测试。

**与团队模式对比**：数据存在浏览器本地，不同步、不协作、不持久（关浏览器前不导出就没了）。

---

## M

### 脑图（Brain Map）

**业务语言**：casemap 的核心 — 一张「测试用例关系图」。每个接口（API）是父节点，这个接口的不同测试用例是子节点，用箭头连起来表示依赖 / 从属关系。

**用户看到的**：打开 casemap 看到的那张彩色图。

**为什么叫「脑图」**：因为结构像大脑神经网络 — 一个中心 + 多个分支。

---

## N

### 内部链接 / Spec 内部引用

**业务语言**：casemap 自动识别接口文档里的 `$ref`、`definitions`，把所有相互引用的接口画在同一张脑图里。

---

## P

### PM（项目经理 / 产品经理）

**业务语言**：在 casemap 里 PM 是「数据拥有者」 — 创建项目、上传接口、邀请 QA、看进度、导出报告。

**详细工作流** → [PM 工作流](./pm-workflow.md)。

---

### pending（未测）

**业务语言**：还没测过的用例。

**用户看到的**：灰色边框的节点。

---

## Q

### QA 测试人员

**业务语言**：在 casemap 里 QA 是「以执行为主」 — 拿到脑图链接和 API Key 后在浏览器里点节点、测用例、标状态、写备注。

**详细工作流** → [QA 测试人员工作流](./tester-workflow.md)。

---

### 区块筛选器

**业务语言**：左侧或顶部的下拉框 / 复选框，让你只看「未测」「失败」「某个接口」。

---

## S

### Spec（接口文档）

**业务语言**：开发写的「接口说明书」，列出了所有 API（路径、参数、返回值）。casemap 从这份文档生成脑图。

**用户看到的**：开发上传的 `.json` 文件。

**常见格式**：

- OpenAPI / Swagger（最常见）
- Postman v2.1
- Apifox（导出 OpenAPI）

---

### 实时同步（Real-time Sync）

**业务语言**：你在 A 浏览器标了什么，B 浏览器 1 秒内自动更新。casemap 用 WebSocket 实现。

**用户看到的**：不需要刷新，脑图自动变。

**技术对应**：WebSocket push。

---

### 失败（failed）

**业务语言**：测试结果和预期不一致。

**用户看到的**：脑图节点变**红色**。

**注意**：失败后必须写备注，描述「实际看到的是什么」。

---

### 跳过（skipped）

**业务语言**：主动选择不测这个用例（比如重复用例、不适用场景）。

**用户看到的**：节点变**紫色**。

---

### Stable ID（stable ID）

**业务语言**：每个测试用例的「身份证号」，由用例内容哈希算出。重新跑脑图生成，stable ID 不变 — 所以 QA 之前标的状态会自动匹配回来。

**用户看到的**：在脑图节点的 HTML 属性里能看到（在开发者工具里看）。

**技术对应**：BLAKE2b hash。

---

## T

### 团队模式（Team Mode）

**业务语言**：casemap 部署在一台服务器上，所有人用浏览器访问同一个项目，所有改动实时同步。

**适用**：QA + PM + 业务方协作。

**与离线模式对比**：数据存在服务器上，自动同步，多设备访问。

---

## W

### WebSocket

**业务语言**：浏览器和服务器之间的「长连接」，让服务器能主动推送消息给浏览器（不然只能浏览器问服务器）。casemap 用它实现实时同步。

**用户看到的**：不需要知道 — 你只要看到节点自动变就行。

---

### 未测（pending）

**业务语言**：还没人测过这个用例。

**用户看到的**：节点**灰色**边框。

---

### 完成率（Completion Rate）

**业务语言**：通过数 / 总数。

**例子**：245 条用例里 180 条通过 → 完成率 73.5%。

**注意**：完成率高不代表可以上线 — 还要看失败数和阻塞数。

---

## X

### 项目（Project）

**业务语言**：casemap 里一个独立的工作区。一个项目 = 一份接口文档 + 一堆测试用例 + 一堆状态。

**用户看到的**：casemap 首页上的卡片列表，每个卡片是一个项目。

---

### 项目 ID

**业务语言**：项目的唯一标识（一串字符）。

**用户看到的**：URL 里的 `/projects/{ID}/...`。

---

### 协作（Collaboration）

**业务语言**：多个人一起在同一个项目上工作。casemap 通过实时同步让协作顺畅 — 谁标了什么别人立刻看到。

---

## Y

### 预览（Preview）

**业务语言**：在正式标记前先看用例的步骤和预期结果。

**用户看到的**：点击节点后右侧详情区。

---

### 预期结果（Expected Result）

**业务语言**：测试步骤跑完后「应该看到什么」。

**用户看到的**：用例详情里的「预期：xxx」。

---

### 用例（Test Case）

**业务语言**：一条测试 = 「做什么 + 怎么做 + 应该看到什么」。

**用户看到的**：脑图上的一个节点 + 右侧的标题 / 步骤 / 预期。

---

### 用例类型（Case Type）

**业务语言**：casemap 把自动生成的用例分成 4 类（按节点填充色区分）：

| 类型 | 颜色 | 业务含义 |
|------|------|---------|
| 正向 (positive) | 浅绿 | 正常流程 |
| 逆向 (negative) | 橙色 | 故意出错 |
| 边界 (edge) | 蓝色 | 极端值 |
| 安全 (security) | 红色 | 权限 / 越权 |

**详细见 [QA 工作流 - 用例类型](./tester-workflow.md#用例类型业务语言解释)**。

---

## Z

### 阻塞（blocked）

**业务语言**：暂时测不了 — 缺账号、缺环境、依赖其他 bug。

**用户看到的**：节点变**黄色**。

**注意**：阻塞要有理由，不然 PM 没法协调资源。

---

### 状态（Status）

**业务语言**：一条用例当前处在什么阶段。

**用户看到的**：节点边框颜色。颜色对应关系见 [QA 工作流 - 状态颜色](./tester-workflow.md#状态颜色的含义)。

---

### 自动生成（Auto-generate）

**业务语言**：casemap 用启发式规则从接口文档自动生成测试用例，不需要 QA 一个个写。

**适用规则**（每条接口自动产出 5–15 条用例）：

- 正向（按必填项全填走一遍）
- 必填校验（少填某个字段）
- 资源不存在（404）
- 鉴权（未登录 / 用错权限）
- 冲突（重复创建）
- 边界（最大 / 最小 / 空 / 超长）
- 删除安全（删前确认 / 软删除）

---

### 备注（Note）

**业务语言**：测试员在标记失败 / 阻塞 / 跳过时写的「为什么」。

**用户看到的**：节点详情下方的文本输入框。

**重要**：失败必须有备注，否则开发不知道哪里出了问题。

---

### 自我包含（Self-contained）

**业务语言**：一个 HTML 文件里包含所有东西（CSS / JavaScript / 数据），不需要外部资源。

**用户看到的**：casemap 离线模式的 `.html` 文件可以直接用浏览器打开 — 不需要联网、不需要 CDN。

---

### 状态导入 / 导出

**业务语言**：把测试状态保存成 JSON 文件，再从 JSON 文件恢复 — 用于跨设备同步 / 备份。

**用户看到的**：「Export Status」「Import Status」按钮。

---

### 执行（Execute）

**业务语言**：测试员按用例步骤在真实环境跑一遍，看结果跟预期是否一致。

---

### 中心节点（Root Node）

**业务语言**：脑图的「中心」 — 通常是一个项目或一个核心接口，其他节点从这里辐射出去。

---

### 重点模块（P0 / P1）

**业务语言**：业务上最重要的功能 / 接口。PM 通常会标 P0 / P1 让 QA 优先测。

**注**：casemap v1 没有内建优先级标签，PM 用 tag 实现。

---
